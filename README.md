# Claude Arch Viewer

Локальный просмотрщик и восстановление архива Claude. Приложение читает ZIP-файлы экспорта Claude прямо в браузере: ничего не загружается на сервер, не требует аккаунта и работает офлайн.

> Статус: **v0.1 MVP**. Основные категории архива уже читаются, чаты, артефакты, проекты, память и Claude Code Cloud отображаются. Дальше — диффы версий, Obsidian, статический сайт и улучшение больших архивов.

## Что умеет

- **Импорт manifest + ZIP**: принимает JSON-manifest из письма и все 7 ZIP-файлов экспорта.
- **Чаты**: список, поиск по тексту, ветки сообщений, `thinking`, вызовы инструментов, результаты, вложения, изображения и документы (метаданные).
- **Артефакты**:
  - **Frames**: полные деревья файлов, версии, `page.md`, комментарии, превью HTML/приложений, скачивание версии.
  - **Из чатов**: восстановление версий из `create` / `update` (`old_str` → `new_str`), просмотр кода и скачивание.
- **Проекты**: описание, инструкции, документы.
- **Claude Code Cloud**: каналы, сообщения, агенты, рутины и транскрипты сессий.
- **Память и рефлексии**: файлы памяти и отчёты feedback.
- **Аккаунт**: пользователи и история входов.
- **Файлы**: полное дерево архива, превью текста, скачивание.
- **Диагностика**: покрытие категорий, типы блоков, предупреждения, файлы без бинарников.
- **Экспорт**: чат в Markdown/JSON/ZIP, проект в ZIP, весь архив в дерево ZIP, lossless-копия raw-файлов.
- **PWA**: установка как приложение, офлайн-режим, тёмная и светлая темы.

## Приватность

Архив Claude содержит личные данные. Приложение:

- не отправляет файлы в сеть;
- не использует аналитику и телеметрию;
- хранит всё в памяти вкладки;
- не коммитит реальные архивы в репозиторий (`samples/` в `.gitignore`).

## Быстрый старт

```bash
npm install
npm run dev
```

Откройте адрес из терминала, перетащите в окно manifest и ZIP-файлы архива.

### Как получить архив

1. В Claude откройте **Settings → Privacy → Export data**.
2. Дождитесь письма со ссылками.
3. Скачайте **все** ZIP из письма (ссылки живут 24 часа).
4. Перетащите в приложение manifest и ZIP-файлы.

Приложение покажет, какие категории уже загружены, а какие ещё нет.

## Поддерживаемые категории

| Категория | Что внутри |
|---|---|
| `light_metadata` | `users.json`, `login_history.json` |
| `projects` | проекты и документы |
| `memories` | файлы памяти |
| `feedback` | рефлексии |
| `frames` | артефакты с файлами и версиями |
| `claude_code_cloud` | каналы, сообщения, агенты, рутины, транскрипты |
| `conversations` | чаты и сообщения |

## Ограничения экспорта Claude

Это не ошибки приложения — этих данных просто нет в ZIP:

- **Оригиналы файлов не экспортируются.** Изображения, PDF и документы есть только как метаданные; у части вложений сохранён извлечённый текст.
- **В старой версии схемы нет `project_uuid` и `model`.** Связь «чат → проект» и модель из архива не восстанавливаются.
- **ID артефактов из чатов и Frames не пересекаются.** Это два независимых источника, поэтому в интерфейсе они разделены.
- **Ссылки на скачивание архива живут 24 часа** и могут перестать работать после первого использования.

Приложение показывает отчёт о покрытии и предупреждения, чтобы было видно, что именно не удалось восстановить.

## Скрипты

```bash
npm run dev          # dev-сервер
npm run build        # production-сборка в dist/
npm run build:single # один HTML-файл для офлайна
npm run preview      # предпросмотр production-сборки
npm run typecheck    # проверка TypeScript
npm test             # unit + UI-тесты (Vitest)
npm run test:e2e     # Playwright e2e (нужен Chromium)
npm run icons        # перегенерировать PNG-иконки
```

## Архитектура

```
src/
  core/
    types.ts          # модель архива
    importer.ts       # импорт и слияние ZIP
    zip.ts            # распаковка
    manifest.ts       # разбор manifest
    artifacts.ts      # восстановление артефактов из чатов
    search.ts         # поиск
    export.ts         # Markdown/ZIP-экспорт
    parsers/          # парсеры категорий
  ui/
    state.ts          # сигналы Preact
    components.tsx    # общие компоненты
    views/            # экраны
  workers/            # зарезервировано под вынос импорта
```

Стек: **Vite + TypeScript + Preact + fflate + marked + DOMPurify + highlight.js**.

## Тесты

- `tests/core.test.ts` — парсеры, артефакты, экспорт, поиск на синтетическом архиве.
- `tests/samples.test.ts` — проверка на реальном архиве из `samples/` (локально; в CI пропускается).
- `tests/ui.test.ts` — рендер интерфейса на реальном архиве (happy-dom).
- `tests/e2e/smoke.spec.ts` — Playwright-сценарий импорта и навигации (локально; в CI пропускается без samples).

## Деплой

GitHub Actions собирает проект и публикует `dist/` на GitHub Pages при пуше в `main`. Для релиза достаточно поставить тег `v*` — workflow приложит single-file HTML к релизу.
